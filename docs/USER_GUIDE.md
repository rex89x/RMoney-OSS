## 機票雷達

路徑：側欄「機票雷達」或 `/flights`（手機可從「旅遊」頁首進入）。頁面有三個分頁：

| 分頁 | 用途 |
|---|---|
| 總覽 | KPI、需要處理清單、各區段價格尺、走勢比較、最划算出遊日期 |
| 航線 | 依航線分組的區段卡片；新增、編輯、暫停、刪除、看單一區段走勢 |
| 使用說明 | 本章的精簡版 |

App 內「使用說明」分頁（`features/flight-watches/components/flight-radar-guide.tsx`）與本章要一起更新。

### 名詞

- **航線**：出發機場 → 抵達機場，例如 TPE → NRT。
- **日期區段**：同一條航線的一段可出發日期，例如「寒假 1/20–2/10」。一條航線可以有多個區段，
  各自有晚數、艙等、航空公司條件、理想價與通知設定，也各自累積價格歷史。
- **行程**：每個區段選**來回**、**單程**或**多點進出**。單程不需要晚數、價格為單程含稅價。
  **多點進出（A 進 B 出 / open-jaw）**：去程飛到 A、回程從 B 飛回（例：TPE → NRT 進、KIX → TPE 出），
  表單多兩格「回程出發（B 出）」「回程抵達」；晚數 = 去程出發到回程出發，價格是同一張多城市機票合計。三種不會混在一起比較。
- **購票方式**（來回與多點進出）：**只要一張票**、**只看拼單程**（去程、回程各買一張單程，可不同航空公司）、
  **兩種都比**（多點進出預設）。拼單程常常比較便宜、也比較容易查到價格，但兩張票互不保障（前一段延誤不會幫你改後段），
  行李也要各自購買。結果裡拼單程會標「拼單程」並列出去 / 回各多少，航線卡會比較「一張票最低 vs 拼單程最低」。
- **較低價 / 常見價**：該區段目前「合理可買到的便宜價」與「一般價位」，都是所有旅客合計的
  含稅價（TWD，依區段是單程或來回）。
- **候選日期**：每次掃描最多保存 12 組具體出發（／回程）日期與價格，盡量分散在不同週與晚數；
  來源有提供時另附航班號、起降時間（當地時間）與飛行時間。
- **歷史最低**：開始追蹤以來看過的最低較低價（被判定為可疑的異常低價不算）。
- **理想價**：你設定的價格上限；目前較低價 ≤ 理想價時標示「達理想價」並可發 Telegram。

### 三種資料來源

每個區段在「掃描方式」選一種：

| 來源 | 費用 | 何時更新 | 適合 |
|---|---|---|---|
| **Claude 排程推送** | 不另付 API 費用（用 Claude 方案額度） | 你在 Claude 設定的排程時間 | 日常追蹤，推薦 |
| Claude API + Web Search | 扣 Claude API 額度（每次約 US$0.05–0.30） | 每天 09:00 或「立即更新」 | 需要隨時手動刷新 |
| Duffel API | 可能有超額搜尋費 | 每天 09:00 或「立即更新」 | 需要可售即時報價 |

Claude 排程推送的區段沒有「立即更新」按鈕，資料只會在排程推送或手動貼上結果時更新。

### 第一次設定 Claude 排程

整體流程：

```
Claude 排程（每天）── 網路搜尋 ──▶ 整理成 JSON
      │  從環境變數 RMONEY_FLIGHT_INGEST_TOKEN 讀 token，放在 POST body
      ▼
Apps Script ingestFlightPrices ── 驗證 ──▶ 區段價格與快照 ──▶ Telegram
```

**1. 設定區段（Personal Hub）**

「航線」分頁新增或編輯區段，選**來回／單程／多點進出**，「掃描方式」選 **Claude 排程推送（不另付 API 費用）**，
「Claude 排程群組」選一個群組或直接輸入新名稱（一個群組 = 一個 Claude 排程任務），儲存。

**2. 產生推送 token（Personal Hub）**

右上「Claude 排程」→「產生 token」→ 複製。token 只顯示一次；不要貼到任何聊天、Issue 或文件。

**3. 建立專用的 Claude 雲端環境（claude.ai）**

1. 打開 <https://claude.ai/code>，在開新 session 的畫面點訊息框下方那一排的第一個控制項（環境選單）
   → 最下面 **New environment**。
2. 名稱：`flight-radar`。用專用環境，避免其他 Claude 工作也帶著這個 token。
3. **Environment variables**：

   ```
   RMONEY_FLIGHT_INGEST_TOKEN=rmfi_剛剛複製的token
   ```

4. **Network access** 選 **Custom**，**Allowed domains**：

   ```
   script.google.com
   script.googleusercontent.com
   ```

   勾選 **Also include default list of common package managers**。第二個網域不能少：
   Apps Script 會把請求轉址到那裡回傳結果。
5. **Add environment** 存檔。

> 環境設定裡另有 **Network secrets**，會由代理在請求標頭加上密鑰；Apps Script Web App 讀不到
> 自訂標頭，所以這裡用環境變數。

**4. 複製排程提示詞（Personal Hub）**

「Claude 排程」→「排程群組與提示詞」→ 點選群組，會列出該群組每個區段與狀態
→「複製『群組名』提示詞」。複製後這些區段會標成「已在排程」。有幾個群組就重複第 4、5 步建幾個排程任務。

**5. 建立排程任務（claude.ai）**

1. 打開 <https://claude.ai/code/routines> → **New task**（若出現選單選 **Set up manually**）。
2. **Name**：`機票雷達每日查價`。
3. **Prompt**：貼上剛剛複製的提示詞。
4. **Trigger** → **Schedule** → **Daily**，時間用台灣時間並避開整點（例如 7:07），整點可能延遲數分鐘。
5. **Advanced settings → General**：
   - **Repository**：`<owner>/<repo>`（要選一個 repo，任務才會以雲端 session 執行；提示詞已要求不修改 repo）。
   - **Cloud environment**：`flight-radar`。
6. **Connectors** 分頁：全部移除，這個任務不需要。
7. 模型選 Sonnet 即可；**Create**。

**6. 驗證**

1. 任務頁按 **Run now**。
2. 跑完後點 **History** 中的該次執行，看到推送回應有 `"accepted"` 大於 0。
3. 回 Personal Hub：卡片價格更新、標示「Claude 排程」；「Claude 排程」對話框顯示最後推送時間。

### 新增航線或多個日期區段之後

- **同航線加區段**：卡片上的「同航線新增日期區段」（複製圖示）會沿用條件、日期往後接續，填一個
  區段名稱（例如「春節」）即可。航線分頁會把同航線的區段放在同一組，依出發日排序。
- **Claude 不會自動知道新區段或條件變更**：Claude 排程用的是你當時複製的提示詞。新增區段、改日期、
  晚數、人數、艙等、直飛、廉航或航空公司條件後：
  1. 「Claude 排程」裡該區段會顯示 **尚未加入排程** 或 **條件已改，需重新複製**，總覽的「需要處理」也會列出。
  2. 重新勾選並複製提示詞。
  3. claude.ai/code/routines → 該任務 → 名稱旁選單 **Edit** → 換掉 Prompt → **Save changes**。
  - 舊提示詞送來的結果會因 `criteriaKey` 不符被拒收，卡片顯示「搜尋條件已變更」，不會用錯條件覆蓋價格。
  - 只改理想價、通知、區段名稱不影響提示詞，不需要重新複製。
- **區段很多時分組**：把區段放進不同 Claude 排程群組（例如日本線、歐洲線），每個群組一個排程任務。
  每次查的區段少，速度與準確度都比較好。群組可在航線表單或「Claude 排程」對話框隨時新增或移動；
  移動後原群組與新群組的提示詞都要重新複製（狀態會顯示「條件已改，需重新複製」）。
- **推送分批**：提示詞內的推送指令會自動每 10 條分一批送出（伺服器單次上限 20 條）。
- **暫停或過期**：關掉卡片開關，或最晚出發日已過的區段，不會出現在提示詞；排程送來也會被拒收。
  不再需要的區段請刪除，然後重新複製提示詞。

### 看懂總覽與首頁卡片

頁面上方的**篩選**（行程：全部／來回／單程／多點、艙等、航線）同時套用到總覽與航線列表。
總覽右上「**調整版面**」可開關、排序各區塊，設定存在帳號裡（換裝置也一樣）。

| 區塊 | 怎麼看 |
|---|---|
| KPI | 追蹤中區段（啟用 / 全部，與航線數）、低於理想價、建議購買、需要處理（不受篩選影響） |
| 目前最低價機票 | 每個區段最便宜的一組日期做成機票樣式：航空公司、航班號、起降時間、飛行時間、出發／回程日、艙等、轉機、人數、價格與是否達理想價 |
| 需要處理 | 更新失敗（附錯誤原因）、Claude 排程超過 3 天沒推送、提示詞過期、尚未加入排程 |
| 哪段時間出發最便宜 | 依出發週分格，越深越便宜，最便宜三週標「推薦」並列出該週最佳日期；下方是週幾出發、住幾晚的最低價 |
| 候選日期評估 | 所有候選日期，可排序（價格／出發日／比最低差距）、篩平日或週五六出發、只看直飛；標示區段最低、直飛最低、達理想價，並顯示比同區段同艙等最低價貴多少 |
| 各區段目前價格 | 同一條 TWD 軸：長條＝目前較低價、圓點＝歷史最低、直線＝理想價 |
| 艙等價差 | 每個區段各艙等的較低價橫條，看商務艙比經濟艙貴多少 |
| 出發日與票價 | 每個點是一組候選日期，依艙等上色，看出哪些日子便宜 |
| 航班時段、航空公司、直飛 | 直飛 vs 轉機最低價、去程出發時段（深夜／上午／下午／晚上）最低價、各航空公司最低價 |
| 較低價走勢比較 | 每個區段每天一點；點選區段切換顯示，最多 8 條。顏色固定跟著區段 |

「哪段時間出發最便宜」「候選日期評估」「出發日與票價」「航班細節」右上有**分析區段**選單，
預設分析目前最便宜的區段；不同航線、單程與來回混著比較會失真，需要時再選「全部區段」。
週幾、時段、航空公司等比較在同一個艙等內進行（沒選艙等時用最便宜那組的艙等，標在說明文字裡）。

首頁 Dashboard 可在卡片設定開啟 **機票雷達**：顯示目前最便宜的 3 個區段與待處理數量，點擊進入機票雷達。

單一區段的完整走勢：航線分頁 → 卡片「價格趨勢」。

### Telegram 通知

每個區段可設定：

- **低價或達理想價時通知**：較低價第一次跌破理想價，或比前次下降超過設定百分比。
- **每次掃描都回報**：每次排程推送或掃描都發目前價格。

Claude 排程推送與 Apps Script 掃描用同一套通知規則。被判定為可疑異常低價的結果不發低價通知。
Telegram 全域開關在「設定 → 通知」。

### 安全設計

- **token 只寫不讀**：只能寫入 token 擁有者、來源為 Claude 排程且啟用中的區段票價；回應不含任何資料，
  外洩也拿不到帳本或行程。
- **伺服器只存雜湊**：token 在瀏覽器產生，Apps Script 只保存 SHA-256。
- **輪替與撤銷**：「Claude 排程」→ 重新產生 token（舊的立即失效）或撤銷。懷疑外洩就重新產生，再更新 Claude 環境變數。
- **伺服器重新驗證**：艙等、日期、晚數、直飛、廉航與航空公司條件；來源必須是 https 網址。
- **異常低價防護**：比前次常見價低 60% 以上會標為低可信度、不更新歷史最低、不發低價通知。
- **流量上限**：每天總計 60 筆、每個區段每天 6 筆。
- **航班細節驗證**：時間必須是 HH:mm、飛行分鐘數 20–3000、航班號格式正確，否則該欄位直接捨棄。

技術細節見 [`INTEGRATIONS_SETUP.md` §1.1](./INTEGRATIONS_SETUP.md#11-claude-排程推送不另付票價-api-費用)。

### 常見問題

| 狀況 | 原因與處理 |
|---|---|
| 「Claude 排程」沒有提示詞 | 沒有任何區段的掃描方式是 Claude 排程推送，或都已暫停／過期。對話框會列出每個區段不納入的原因 |
| 卡片顯示「搜尋條件已變更」 | 條件改過，重新複製提示詞並更新排程任務的 Prompt |
| 執行紀錄出現 `403` / `host_not_allowed` | 雲端環境的 Allowed domains 少了 `script.google.com` 或 `script.googleusercontent.com` |
| 執行停在等待確認 | 部分動作在 auto mode 仍會詢問；打開該次執行按允許 |
| 執行顯示 Succeeded 但價格沒更新 | Succeeded 只代表 session 正常結束；打開該次執行看推送回應的 `results[].error` |
| 排程無法連網或推送失敗 | Claude 會在回覆輸出 JSON；整段貼到「Claude 排程 → 貼上結果」，驗證規則相同 |
| 「此航線今日匯入次數已達上限」 | 同一區段一天最多 6 次；隔天自動恢復 |
| 要換 token | 重新產生 → 更新 Claude 環境變數；下一次執行生效 |
| 網頁看起來還是舊版 | PWA 快取；手機把 App 完全關掉再開，電腦強制重新整理 |

## 股市雷達

側欄「股市雷達」（`/stock-radar`）。每天評估「投資」頁的**持股與自選股**，台股、美股各一份。

| 分頁 | 看什麼 |
|---|---|
| 今日 | 大盤燈號、盤前輿情、需要處理的持股、加碼與買進候選、與上次相比的變化、持股健康度 |
| 個股 | 各因子分數、量化與輿情各占多少、停損價、輿情摘要與來源連結、分數與股價走勢 |
| 成績單 | 過去建議的事後表現：命中率、IC、各動作的超額報酬、輿情有沒有幫到 |
| 回測 | 用 5 年日 K 驗證公式：淨值曲線、分數區間報酬、vs 大盤 |
| 使用說明 | 因子定義、論文出處、動作門檻、限制 |

### 每天的流程（台北時間）

| 時間 | 做什麼 |
|---|---|
| 01:00 | 同步前一交易日台股三大法人、融資餘額 |
| 07:30 | Claude 台股排程上網整理輿情並推送 |
| 08:00 | 評估台股與美股，合併已收到的輿情；Telegram 推播台股建議 |
| 20:30 | Claude 美股排程推送 → 重新合成美股並推播 |
| 21:00 | 美股若沒收到 Claude 推送，推播純量化結果 |
| 週日 20:00 | 重新回測 |

### 第一次設定 Claude 排程

1. 股市雷達 → 右上「Claude 排程」→ 產生 token，立刻複製。
2. 在 Claude 的雲端環境設定加環境變數 `RMONEY_STOCK_INGEST_TOKEN`，並允許連線 `script.google.com`、`script.googleusercontent.com`（可以和機票雷達共用同一個環境）。
3. 切到「台股」複製提示詞，在 Claude 建立「週一到週五 07:30」的排程；切到「美股」複製，建立「週一到週五 20:30」的排程。
4. 持股或自選股有改：先按「重新評估」，再回來重新複製該市場的提示詞（對話框會提醒）。

排程沒辦法推送時，Claude 會在回覆輸出 JSON，整段貼到「Claude 排程 → 貼上結果」即可。

### 看懂建議

- 持有中：**加碼 / 續抱 / 減碼 / 出場**；自選股：**買進候選 / 觀望 / 避開**；歷史不足顯示「資料不足」。
- 大盤偏空時不建議加碼；跌破停損價至少減碼；單檔占股票部位 ≥ 25% 不建議再加碼；近期有財報或重大事件暫緩加碼與買進。
- 輿情最多影響分數 ±0.3，沒有來源不計分；Claude 看不到你的股數和成本。
- 成績單的「方向命中率」50% 等於擲硬幣，IC > 0.05 已屬不錯；樣本少時不要過度解讀。
- 回測用的是目前清單，有倖存者偏差，結果偏樂觀。
- 只提供決策參考，不會自動下單，也不構成投資建議。

## 台指期模擬

側欄「台指期模擬」（`/taifex`）。用台指期近月連續日 K 跑**日線波段策略**的虛擬帳戶：每天收盤後算訊號，隔天開盤以虛擬單成交。
不接券商、不會下真實委託。策略與架構見 [`TAIFEX_PAPER_TRADING_PLAN.md`](./TAIFEX_PAPER_TRADING_PLAN.md)。

| 盤中技術 | 日盤 + 夜盤的技術指標模擬：每 5 / 15 / 30 / 60 分鐘看一次盤的成績比較、日盤 vs 夜盤、開盤後多久進場、最近一次判斷的指標；休市時顯示原因與下次開盤 |

### 第一次使用

1. 打開「台指期模擬」→ 按「回補歷史資料」（約 1–2 分鐘），會抓 2 年期交所日 K、三大法人、PCR，並建立 100 萬的微台虛擬帳戶。
2. 到「設定」確認契約與風險；換契約或起始資金要按「重置帳戶」才生效。
3. （選用）右上「Claude 輿情」→ 產生 token，存成 Claude 雲端環境變數 `RMONEY_TAIFEX_INGEST_TOKEN`，
   複製提示詞建立兩個排程：週一到週五 07:30、17:00。

### 每週檢討與參數調整（選用）

讓 Claude 每週日檢討這一週的表現，必要時提出參數調整；**提案要你核准才生效**。

1. 「AI 分析 → MCP 連線」：確認 Claude 已授權，並對那個連線開啟「允許寫入」（它只能存提案，改不了參數）。
2. 「台指期模擬 → 週檢討 → Claude 排程設定」複製提示詞，在 Claude 建立每週日 21:30 的排程，連接 Personal Hub connector。
   想讓它在需要改公式時直接開 Pull Request，排程再加上這個專案的 GitHub repo。
3. 有提案時 Telegram 會通知。到「週檢討」看每一項「目前 → 提案」與回測對照（樣本外 / 完整期間），按「套用」或「退回」。
4. 套用日線門檻或因子權重後，主帳戶會切到「Claude 調校」策略變體；不滿意可以按「還原最近一次套用」。

可以調的只有四區，每一項都有寫死的上下限：日線門檻與停損、日線因子權重（總和固定 1）、資金管理（每筆風險 0.25–3%、最大口數 1–20、熔斷 5–40%、是否放空）、
盤中技術模擬規則。單週輸贏不是調整的理由；樣本外回測變差的提案不要套用。

### 每天的流程（台北時間）

| 時間 | 做什麼 |
|---|---|
| 07:30 / 17:00 | Claude 排程推送市場輿情與事件行事曆 |
| 08:00 | 補跑前一天（若 18:00 失敗）→ 盤前否決 → 推播今日下單建議 |
| 08:45–13:45 | 每 5 分鐘盤中模擬：開盤成交、盤中停損、接近停損提醒 |
| 08:45–13:45、15:00–隔日 05:00 | 盤中技術模擬（日盤 + 夜盤）；週末、國定假日、臨時休市不跑 |
| 18:00 | 抓期交所資料 → 收盤結算 → 新訊號 → 明日下單建議 → Telegram（21:00 再補跑一次） |
| 週日 20:00 | 回測 + 參數最佳化 |
| 週日 21:30 | （選用）Claude 排程做每週檢討，送出參數調整提案 |

### 盤中模擬與下單建議

- 平日 08:45–13:45 每 5 分鐘用即時報價模擬：待成交單以開盤價成交、盤中觸發停損、距停損 0.5 ATR 內提醒（Telegram）。
- 預設用加權指數 + 基差推估期貨價格（畫面標示「推估價」）。要用台指期實際報價：到 [Fugle](https://developer.fugle.tw/) 申請行情 API key，
  在 Apps Script → 專案設定 → 指令碼屬性加 `FUGLE_API_KEY`。
- 總覽的「下單建議」把待成交單翻成券商下單步驟（限價 / 範圍市價、ROD / IOC、成交後的停損單價格）；08:00 會依夜盤更新並推播。
  虛擬帳戶會自動成交，這張單是給練習實單或之後接券商前核對用。
- 盤中下的手動單以即時價成交；收盤後或盤前下的單在下一個交易日開盤成交。

### 績效與策略競賽

- 「績效」分頁：總報酬、年化、Sharpe、最大回撤、vs 同期大盤、每月報酬，以及白話結論。未滿 60 個交易日且少於 10 筆交易時會顯示「樣本不足」，先不要依幾天的數字調策略。
- 策略競賽：基準 / 保守 / 積極 / 最佳化四組參數各跑一個虛擬帳戶，依總報酬排名。主帳戶要跟哪一組在「設定」選。
- 報酬最大化測試：每週日用前 60% 歷史找報酬最高的參數，再用後 40% 驗證；只有樣本外也贏基準才算有效。另會建議「每筆風險%」上限。
- 重置帳戶會連策略變體一起重置，讓比較從同一天開始。

### 看懂訊號

- 合成分數 −1 ~ +1；空手時 ≥ +0.35 且趨勢向上才做多（做空對稱），持倉中回到 ±0.05 以內才平倉。
- ADX < 18 視為盤整，分數打 6 折；下一個交易日有 FOMC / CPI / 央行等重大事件時不新開倉。
- 輿情最多影響 ±0.2，沒有 https 來源不計分。
- 「資金不足以符合風險預算（0 口）」：停損距離 × 每點價值超過每筆風險預算，改用微台或提高資金 / 風險%。
- 趨勢策略勝率常常低於 50%，靠「賺多賠少」；看獲利因子與期望值比勝率重要。

### 手動下單

總覽 →「手動下單」：填的是成交後的**目標部位**（多 N 口 / 空 N 口 / 全部平倉），下一個交易日開盤價成交。
自動模式下手動單優先，不會被自動訊號覆蓋；待成交單可在總覽取消。

### 盤中技術模擬（日盤 + 夜盤）

「盤中技術」分頁是獨立的實驗帳，不影響主帳戶。交易時間每 5 分鐘取一次報價，四個虛擬機器人分別每 5 / 15 / 30 / 60 分鐘
看一次盤，用同一套技術指標（均線、MACD、RSI、通道）虛擬進出場，收盤前一律平倉。用來看：

- **多久看一次盤比較好**：監控頻率比較（淨損益、勝率、獲利因子、每次查看的平均損益）。
- **日盤還是夜盤**：兩個時段分開統計。
- **開盤後多久進場**：依進場時間分段的每筆平均損益。

要點：

- 5 分頻率約 3 小時後開始有決策，60 分頻率要累積約 2 個交易日；至少 30 筆交易再比較。
- **休市不模擬**：週末、證交所公告的休市日、設定頁的「自訂休市日」（颱風假），以及報價超過 45 分鐘沒更新。
- 夜盤報價需要 `FUGLE_API_KEY`（Apps Script 指令碼屬性）或期交所行情資訊網可連線；取不到時分頁會顯示「取不到夜盤報價」。
- 設定頁可個別關閉日盤 / 夜盤、調整每次口數、開啟進出場推播（預設關，夜盤會在半夜通知）。
- 之後調整演算法（升版本）請按分頁最下方「重置技術模擬」，新舊成績分開看。

| 狀況 | 處理 |
|---|---|
| 顯示「資料偏舊」 | 按「立即更新」；仍舊就是期交所當天沒資料（假日）或下載失敗，Telegram 錯誤通知會說明 |

## 共同公基金

在「共同」→「公基金」分頁。兩人把錢放進同一個公基金，部分共同支出直接從公基金付。

### 每月固定投入與固定扣款

1. 公基金分頁按「開始設定」（之後是「調整」），填：
   - **每月幾號存**、**從哪個月開始**（之前的月份不會回補）
   - **每人每月投入**金額
   - **到日自動記錄存入**：已經設定銀行自動轉帳就打開，系統會在當天 01:00 替兩人各記一筆；
     關閉時卡片顯示「待存入」，各自按「記錄存入」。
   - **固定從公基金扣款**：房租、水電、網路、共同訂閱……每筆設金額、類別、每月幾號。
2. 到日（台北 01:00）系統自動從公基金記一筆共同支出（公基金付款，不會變成兩人之間的欠款）。
   等不及可以按「立即扣款」，同一個月只會有一筆。
3. 卡片下方顯示每月存入、固定扣款、近 3 個月其他公基金支出平均與**每月淨流入**；
   淨流入是負的時候會提醒「目前餘額還能撐幾個月」。

### 記共同支出：預設由帳本（公基金）負擔

新增共同支出時，「記帳方式」預設是**帳本負擔（公基金）**，不用選誰付、誰負擔。只有例外才改：

- **各付一半**：一人先付，兩人平分。
- **代墊：另一人全額負擔**：一人先付，但這筆全算對方的（例如替對方買東西）。
- **其他分法**：依比例或自訂金額。

選「帳本負擔」時，下面可以標示**實際由誰付出去**：

- **公基金直接付**：用公基金的帳戶 / 卡片付的。
- **某人先墊**：例如 owner 用自己的卡付了全家的晚餐。費用仍由帳本負擔，但公基金欠 owner 這筆錢。

之後到「公基金 → 公基金待撥還」會看到每個人先墊多少、已撥還多少、還欠多少。實際從公基金轉帳給他之後，
按「撥還」記錄就結清（可以部分撥還）；如果收款的是你自己，可以勾「同時記到我的帳本」讓帳戶餘額加回來。
公基金的「帳上可用」已經扣過這些支出，撥還不會再扣一次；「實際現金」才會減少。

**讓另一半也能處理撥還**：「設定 → 成員與權限」的「公基金管理」預設是打開的，對方就能看到並記錄撥還、調整每月計畫。
在「公基金 → 公基金轉帳待辦」可以指定**保管人**（公基金帳戶在誰手上）；之後保管人會在總覽、首頁卡片與 Telegram 報告看到
「請從公基金轉 NT$X 給某人」，轉完按「已轉，記錄撥還」即可。

公基金餘額不夠時仍可以存檔，會提醒餘額變負，記得補存。歸入旅程的支出不能用公基金，會改成由自己付。

### 記帳之後修改公基金支出

- 公基金分頁的流水帳每一列都能點：支出 → 看明細 → **編輯**（金額、類別、日期，或改成由個人付款）或刪除
  （刪除後金額回到公基金）；存入 → 直接修改金額、日期、備註。
- 「交易」分頁的公基金存入也有「修改」。
- 自動扣款的那筆刪掉後，這個月不會再被補扣；自動存入那筆刪掉也不會隔天又出現。

### 預算與分析

- **總覽 → 本月脈動**：目前已花、照目前速度的月底推估、剩餘每天可花；進度條上的直線是本月時間進度，
  花費條超過它代表花得比時間快。按「預算」可設每月總預算與各類別預算（會顯示近 3 個月平均當參考）。
- **分析分頁**：選近 3／6／12 個月，和前一段同樣長度的期間比較：
  - 每月共同支出（含 3 個月移動平均與預算線）
  - 類別趨勢、類別增減
  - 兩人分工：各自付了多少、應負擔多少、存了多少公基金
  - 星期幾花最多
  - 公基金餘額走勢、每月存入 vs 支出
  - 大筆支出（點開可修改）
